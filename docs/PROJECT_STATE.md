# AutoVisualSkill Project State

Last reviewed: 2026-05-28.

This note is a compact handoff for maintainers and future agents. It mirrors
the code as it exists now; update it when the implementation changes.

## Current Scope

AutoVisualSkill generates reusable visual-skill artifacts for multimodal
agents. A generated artifact typically contains:

- `skill.md`: human-readable visual reasoning protocol;
- `manifest.json`: machine-readable integration metadata;
- optional `assets/`: static priors, runtime-state references, or interleaved
  visual references;
- provenance/config/warning files for auditability.

The project is currently positioned around three user-facing visual skill
kinds:

| Kind | Purpose | Typical examples |
| --- | --- | --- |
| Static | Clarify reusable spatial conventions. | Button hitboxes, table cells, chart projection |
| Dynamic | Render intermediate state back onto the task image. | Counting anchors, line traces, checked candidates, slide critique regions |
| Interleaved | Keep text steps or style/workflow rules adjacent to visual evidence. | Video proof keyframes, documentation screenshots, multimodal chat evidence |

`prior_kind` remains the internal execution mechanism (`none`, `static`,
`dynamic`). `visual_skill_kind` is the public taxonomy (`text`, `static`,
`dynamic`, `interleaved`).

## Current Input Surface

Implemented in `autovisualskill/nodes/parse_input.py`:

- local image files;
- local text-like files: `.txt`, `.md`, `.json`, `.csv`;
- accessible URLs, with visible text and embedded images;
- local video files: `.mp4`, `.mov`, `.webm`, `.avi`, `.mkv`.

Video input is keyframe-based v1: the system samples approximately 1 FPS
candidate frames and asks the VLM to select useful frames up to
`max_video_frames`. It does not process audio, ASR transcripts, subtitles, or
full temporal action semantics.

Known gap: `autovisualskill/media/pdf_proc.py` exists but is not currently wired
into `parse_input.py`; Word input is not implemented. Do not describe PDF/Word
input as supported until this is connected, tested, and documented.

## Public Showcase State

The README gallery currently has four major surfaces:

- Video demos for actual held-out task execution.
- Static visual convention examples.
- Dynamic runtime-state examples.
- Interleaved evidence-binding examples.

The current recorded downstream model for task comparisons is
`gemini-3-pro-preview` through an OpenAI-compatible endpoint. API credentials
were supplied through environment variables and are not stored.

Important recorded task examples:

- Dense counting: direct run counts `64`; visual-skill run counts the correct
  `96` red target tokens with visible anchors.
- Odd-one-out search: direct run selects row 11, column 7; visual-skill run
  selects row 8, column 12 after visible candidate checks.
- PPT critique-and-redraw: the showcase emphasizes region-marked critique state
  before redraw, not only generic text advice.
- ARC-AGI route-state planning: uses the public ARC-AGI-3 `ls20` environment
  rendered through the official `arc-agi` toolkit. The current showcase animates
  the same official episode from a shared prefix: Gemini direct chooses
  `ACTION2` / down and goes off-route, while the dynamic route-state overlay
  keeps the visual-skill branch on the official route. This is a qualitative
  showcase, not a scorecard result.

Most GIF demos are generated by `tools/render_video_demos.py`; the ARC-AGI
route demo is generated by `tools/render_arc_route_demo.py` because it depends
on the official ARC environment frames. GIF writers use Pillow with explicit
positive frame duration and `loop=0`; keep that behavior because GitHub can
appear to show a static final frame when a GIF has zero-duration frames.

## How Agents Should Use Generated Skills

For static skills, attach the task image, `skill.md`, `manifest.json`, and any
visual-prior assets to the VLM call.

For dynamic skills, run an outer loop:

1. send the current task image plus `skill.md`;
2. parse a state update such as anchors, traced edges, or critique boxes;
3. render that state back onto the original task image;
4. send the rendered image into the next call.

For interleaved skills, preserve source order and require each reasoning step
to cite or stay adjacent to the visual reference it depends on.

`examples/agent_integration_minimal.py` is the minimal adapter showing how to
load `skill.md`, `manifest.json`, and assets into a provider-agnostic payload.

## Common Commands

Static checks:

```bash
git diff --check
PYTHONPYCACHEPREFIX=/tmp/autovisualskill_pycache python -m compileall autovisualskill demo_gradio.py examples tools
python -m json.tool examples/task_execution_cases/task_execution_results.json >/tmp/task_execution_results.check.json
```

Offline smoke:

```bash
python examples/mock_smoke.py
```

Regenerate README task visuals:

```bash
python tools/render_task_outcome_comparisons.py
python tools/render_video_demos.py
```

Live task execution evaluations require `LLM_API_KEY`, `LLM_BASE_URL`, and
`LLM_MODEL_NAME`; use `AUTOVISUALSKILL_EVAL_CASES=counting` or another case key
to rerun a subset.
